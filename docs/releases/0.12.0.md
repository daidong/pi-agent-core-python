# 0.12.0：核心接口对齐与研究便利层

0.12.0 在同一个包内增加 `pi_python.core`，用于对接 Pi 对应的钩子、事件和低层循环合同。日常研究继续使用 `pi_python.Agent`、`@tool`、`RunResult`、同步调用及插件。两个入口共用执行引擎，无需另装扩展包，也不要求现有应用切换入口。

本版本包含消息/事件格式和请求行为变化。使用严格解析器、跨版本历史读写或自定义模型网关的应用，应先完成下列迁移，再升级生产环境。

## 主要变化

- **核心入口**：上下文式工具钩子、部分结果覆盖、独立的请求/轮次更新类型、完整对应事件载荷和三参数自定义流。核心低层继续规则与预先取消的生命周期按上游处理；研究入口保留便利重试、自动缓存会话和旧钩子签名。
- **事件流等待**：`result()` 不再依赖继续消费事件，也不吞掉未读事件。研究低层流在等待结果后解除背压；核心流无界。等待结果而不消费时，剩余事件会保存在内存中。
- **请求设置**：模型端点、headers、采样默认值贯通直接 Provider；支持逐请求 `timeout_ms`、`max_retries`、`max_retry_delay_ms`。观察回调可接收模型参数，旧单参数回调保留按签名适配。
- **耗时及身份**：默认输出可测得的 `duration_ms`，增加可配置客户端身份。默认品牌仍为 pi-python，不冒用官方 Pi 应用身份。
- **选择性上游更新**：OAuth 刷新在取消时完成令牌轮换写回；改进恢复分类、跨模型 reasoning、工具变更与空白结果转换、Anthropic 错误图片顺序及模板空参数处理。模型目录更新到固定 npm v1.4.0 快照。
- **既有修复纳入发布**：保留 OpenAI reasoning 的完成事件信息；支持 Anthropic 无参数工具的空参数增量。
- **发布验证准备**：上游源码在目标目录旁解压，避免 GitHub runner 的临时目录与工作区跨磁盘时 rename 失败；来源哈希校验保持不变。

## 现有应用升级清单

| 使用方式 | 需要处理的变化 |
|---|---|
| 普通 Agent、函数工具、RunResult、旧 Hooks | 保留原调用方式；无需改为 core.Agent |
| 严格消息、事件、ToolOutcome 解析 | 接受可选 `duration_ms`；dataclass 序列化可能包含 None |
| 历史持久化和跨服务交换 | 写出消息 schema 4、研究事件 schema 2；新版仍读旧 3/1，旧版不能读新版输出。先升级读取端，再升级写入端 |
| 严格 ModelInfo 序列化 | 接受 headers、sampling_params、sampling_params_by_thinking_level |
| 自定义模型端点或认证头 | 显式 ModelInfo.base_url 优先；header 顺序为 Provider 默认→模型→请求，大小写无关，None 可移除默认头 |
| 请求代理、白名单、审计或快照 | 核对工具/推理配置请求形状、身份头、缓存前缀和新的超时/重试选项 |
| Codex 模型名固定配置 | 目录不再内置 gpt-5.5、gpt-5.3-codex-spark；选择账号可用模型或显式提供核实过的 ModelInfo |
| OAuth 凭据持久化 | 取消等待刷新及写回收尾，持久化回调须能结束；不提供跨进程刷新锁 |
| 主动迁移到 core.Agent | prompt 返回 None；迁移事件消费者、钩子、工具及流签名，见双入口指南 |

严格订阅者拒绝新字段时，工具副作用可能已经完成，随后运行才报告订阅失败。应用应根据执行结果判断是否可以重试，不能把运行失败等同于工具未执行。

升级安装：`pip install --upgrade 'pi-python-core==0.12.0'`。只保存消息不会保存研究 Agent 的缓存会话标识，已有 0.11.0 的会话恢复方式不变。

## 对齐范围与验证

原有核心行为差分保留 Pi v1.0.0 基线，新增接口探针及选择性 Provider/插件更新对照固定 v1.4.0。完整来源与两项后续 main 修复的提交记录见[上游跟进说明](../UPSTREAM_FOLLOWUP.md)。这不是整个 Pi 的完整移植；保留 Python 状态副本、严格验证、时间戳单位和 asyncio 取消清理规则。

合入无参数工具修复后，本地完整测试 962 项通过、2 项跳过，20 项验证命令全部通过。wheel 和源码包通过 twine 严格检查；wheel 在仓库外 Python 3.11 环境安装后，基础示例及双入口示例通过。本地验证记录在 [verification.json](../../compat/results/verification.json)，接口探针记录在 [interface-audit.json](../../compat/results/interface-audit.json)。发布工作流要求跨平台测试、已安装 wheel 示例及上游差分通过后，再构建并上传 PyPI；实际远端结果以本标签的 GitHub Actions 为准。旧 Linux 本地记录不证明本轮新增代码。

真实模型账户、外部数据库、代理部署和各研究 app 尚未逐一验证。离线测试不能保证全部上层应用兼容，也不证明缓存命中率或模型效果。

## English upgrade summary

Keep `pi_python.Agent` for research conveniences; use the new `pi_python.core` only when adopting the corresponding Pi contracts. Both entry points share one engine and package. This release writes message schema 4 and research-event schema 2, reads the previous 3/1 formats, adds timing/model-record fields, and changes shared provider endpoint/header/request-option behavior. Upgrade strict readers before writers, review custom gateway configuration, and test application integrations. See the [English migration guide](../CORE_AND_RESEARCH.md) for callback signatures, precedence rules and remaining Python differences.
