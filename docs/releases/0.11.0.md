# 0.11.0：Codex 默认缓存会话，不改变连接复用

使用 Codex 订阅通道的应用过去需要自行提供 `session_id`，漏传时不会自动发送稳定的会话请求头。本版本由 Agent 默认管理缓存标识，减少这种遗漏。自动标识只用于缓存，不会启动 WebSocket 连接复用或上一响应续接。

## 使用与生命周期

- `Agent(auto_session_id=True)` 为主动声明支持的 Provider 提供稳定标识；内置 Provider 中只有 `OpenAICodexProvider` 开启。core 不按模型名或特定 Provider 类分支，自定义 Provider 和流保持原有合同。
- 同一 Agent 的工具循环、后续请求、重试和配置替换复用标识；不同 Agent（包括子 Agent）独立生成。`reset()` 后换新标识。
- `agent.cache_session_id` 读取 Agent 管理的后备标识。与历史一起保存后，用 `Agent(cache_session_id=saved_id, messages=..., ...)` 恢复；恢复后仍不启用连接复用。
- 应用显式 `session_id` 优先，沿用原有传输语义及 reset 行为。自定义请求头也不会被自动头覆盖。
- `auto_session_id=False` 恢复旧默认；`options={"cache_retention": "none"}` 停止库自动设置缓存键和关联会话头。
- `require_features(["codex-auto-cache-session-v1"])` 可检查是否支持此合同。

## 兼容性与迁移

未传 `session_id` 的 Codex Agent 请求现在会包含 `prompt_cache_key`、`session-id` 和 `x-client-request-id`。严格检查请求内容、快照或自定义网关的应用需要接纳这些字段，或用 `auto_session_id=False` 保持旧请求形状。默认仍为 SSE；自动值不会让已有 `auto` 模式开始复用连接，`websocket-cached` 仍要求应用显式提供 `session_id`。

消息编码与历史格式、事件和运行结果字段不变。自动标识通过独立的请求元数据传递，不加入 `ModelRequest` 的 dataclass 字段或 `request.options`。只保存消息不会保存缓存会话；需要跨进程复用的应用须另外保存 `cache_session_id`。应用自己管理显式 `session_id` 时，仍应保存自己的配置。

这是对官方 Pi core 的有意扩展：上游底层 Agent 不生成标识，上层 coding-agent 才生成并传入；Python 在主要接入入口补齐该职责。固定参照仍为 Pi v1.0.0。通用 core 仅识别可选能力，其他内置通道不增加自动缓存字段。直接调用 Provider 的应用仍自行管理会话。

这一默认行为变化已在实施前经用户确认。库内测试不等于所有实际上层应用兼容。固定版本环境只有升级后才获得此行为。

## 验证范围

验证覆盖请求头与缓存键、跨轮次与重试、子 Agent 隔离、重置与恢复、显式配置优先、禁用和自定义 Provider。WebSocket 检查使用本地服务器，核对连接次数、完整输入和续接字段。缺少默认会话头的回归测试已在修改前的版本上确认失败。

本地全量测试 832 通过、2 跳过；Ruff、格式、mypy 和全部上游差分检查通过，其中核心差分覆盖 25 组。两项跳过适用于不支持 `meta` 的旧版 MCP SDK。完整记录见 [verification.json](../../compat/results/verification.json)。验证运行器的单命令超时临时放宽至 600 秒，仓库脚本未修改。

wheel 与源码包通过 `twine check --strict`。wheel 在仓库外的独立 Python 3.11 环境中安装后，版本检查、基础示例与 78 项缓存、WebSocket 和应用兼容性定向测试通过。发布标签为 `v0.11.0`，远端验证与构建通过后才上传 PyPI。

首次远端 Windows / Python 3.11 检查发现已有运行超时测试的时序假设：20 毫秒期限可能在工具启动前到达。断言现接受运行超时后的“未启动”或“已取消”，工具自身超时仍要求“已取消”；运行实现没有改变。修正后本地相关定向测试 88 项通过。

没有用这些离线结果宣称真实 Codex 缓存命中率、订阅配额节省或所有模型效果。服务端是否命中应通过实际 `cache_read` 用量观察。
